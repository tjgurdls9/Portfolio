# Portfolio — 서혁인

AI를 활용해 업무 문제를 해결한 세 가지 사례입니다. 현업에서 사용한 지원사업 공고 선별 도구의 소스, SKALA 교육 중 개발한 학습 보조 앱의 배포 정보, 의류회사 실무자의 요청으로 만든 작업지 정리 앱을 정리했습니다.

| 프로젝트 | 해결하려고 한 문제 | AI가 맡은 역할 | 위치 |
| --- | --- | --- | --- |
| 지원사업 공고 선별 도구 | 반복적인 공고 확인에서 자사에 검토할 가치가 있는 대상을 추리는 부담 | 기업 조건과 공고 내용을 비교해 후보 및 검토 사유 생성 | [`01_Crawler/crawler.py`](01_Crawler/crawler.py) |
| SKALA FastTrack | 여러 교재에서 학습할 개념과 순서를 정하고 설명 자료를 준비하는 부담 | 교재에서 개념과 관계 추출, 설명과 퀴즈 생성 | [배포 저장소](https://github.com/tjgurdls9/SKALA-FastTrack-releases) |
| Sketch Cleaner | 의류 작업지 사진에서 도해 주변의 글씨와 표시를 하나씩 지우는 부담 | 글씨 위치 감지, 도해 안 표시의 삭제 후보 제시 | [sketch-cleaner](https://github.com/tjgurdls9/sketch-cleaner) |

지원사업 도구의 실제 엑셀 산출물과 내부 보고 자료는 회사 내부 정보이므로 포함하지 않았습니다.

## 1. 지원사업 공고 선별 도구

### 문제와 담당 역할

식품 제조·유통사의 프로젝트팀에서 지원사업 조사와 다른 과제를 병행하면서 여러 기관의 공고를 반복적으로 확인해야 했습니다. 모든 공고를 같은 깊이로 읽기보다 소재지, 업종, 근로자 수, 보유 인증, 사업 관심 분야를 기준으로 검토 대상을 먼저 선별하도록 업무를 구성했습니다.

판단 조건을 정하고 생성형 AI의 도움을 받아 Python 도구를 제작했습니다. 수집한 공고의 내용을 Gemini API로 분석하고 출력된 사유를 원문과 대조하며 판단 기준을 수정했습니다. 이 저장소의 코드는 기업마당을 대상으로 한 버전입니다. 원래 업무에서 확인하던 여러 사이트 전체를 자동 수집한다는 의미는 아닙니다.

### 처리 과정과 AI의 역할

1. Python의 requests와 BeautifulSoup으로 기업마당 공고 목록과 상세 내용을 수집합니다.
2. 제목에 드러난 지역 조건으로 일부 공고를 사전 제외합니다.
3. 기업 조건과 관심 사업 분야를 공고 제목, 본문과 함께 Gemini에 전달합니다.
4. Gemini가 `MATCH` 또는 `SKIP`과 사유를 반환합니다. 사람이 확인할 기회를 놓치지 않도록 경계 사례를 넓게 채택하는 기준을 사용했습니다.
5. 채택 후보는 공고명, AI 분석 내용, 원문 링크의 세 열로 엑셀에 저장합니다. 기각 사유와 처리 오류는 콘솔에 출력합니다.
6. 엑셀에 최종 출력된 목록을 담당자의 최종 검토 대상으로 사용합니다. 원문과 세부 신청 조건을 확인한 뒤 착수 여부를 판단합니다.

수집과 파일 저장은 일반 프로그램 로직이며 AI는 정형화되지 않은 공고 본문을 기업 조건에 비추어 해석하는 데 사용했습니다. 지원 가능 여부의 확정과 실제 신청 결정은 담당자가 수행했습니다.

### 결과물과 업무 활용

수작업으로 공고를 찾고 내용을 확인하던 업무에, AI가 선별한 후보와 검토 사유를 엑셀로 받아 검토하는 절차를 도입했습니다. 엑셀에는 원문 링크를 함께 남겨 판단 근거를 확인할 수 있도록 했습니다. 채택 사유는 사업 착수 전 상부 승인 자료에도 활용했습니다.

실제 출력 엑셀과 내부 보고서는 회사 내부 정보를 포함하므로 이 저장소에서 제외했습니다. 소스에서 수집, 판단 조건, AI 호출, 오류 대응, 엑셀 저장까지의 흐름을 확인할 수 있습니다.

### 실제 구현에서 다룬 문제

API 요청 제한과 일시적인 서버 과부하에 대응하기 위해 호출 전 대기, 오류 종류 확인, 재시도를 넣었습니다. 보존된 코드에서는 호출 전 15초를 대기하고 429 또는 503 등의 오류가 발생하면 60초 대기 후 최대 총 3회 시도합니다. 처리하지 못한 건은 오류로 표시합니다.

### 구현 범위와 한계

이 도구의 출력은 검토 후보입니다. 지원 자격을 확정하거나 지원금 수주를 보장하는 결과가 아닙니다. 보존된 버전은 본문 앞 3,500자를 사용하고 응답의 `MATCH` 포함 여부로 분류하므로 긴 공고의 조건 누락이나 응답 형식의 혼재가 발생할 수 있습니다. 따라서 담당자의 원문 확인을 업무 절차에 포함했습니다.

이 저장소의 코드는 당시 활용한 코드의 보존본입니다. 현재 사이트 구조와 모델 제공 상태에 따른 실행 가능성은 이 저장소를 정리하며 다시 확인하지 않았습니다.

### 코드 확인 및 실행

Python 3 환경에서 아래 패키지가 필요합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests beautifulsoup4 pandas openpyxl google-genai
```

`crawler.py`의 `MY_API_KEY`에 실행자 본인의 Gemini API 키를 설정하고 `MODEL_NAME`이 해당 계정에서 사용 가능한 모델인지 확인합니다. 소스의 키 값은 안내 문구이며 실제 키가 아닙니다.

```sh
python crawler.py
```

실행하면 기업마당에 접속하고 Gemini API를 호출합니다. API 이용량과 계정 조건에 따라 비용이 발생할 수 있습니다. 목록 최대 20페이지를 순회하고 건별 대기 시간이 있어 전체 실행에는 시간이 걸립니다. 채택 후보가 있으면 실행한 위치의 `공고분석결과` 폴더에 날짜와 시간을 포함한 엑셀 파일이 생성됩니다.

## 2. SKALA FastTrack

### 개발 배경과 역할

SKALA 교육 중 여러 교재의 개념과 선후관계를 정리하고 학습 순서를 구성하기 위한 개인 개발 프로젝트입니다. 기획, 백엔드, 프론트엔드, 앱 패키징과 배포를 수행했습니다. 학습 자료를 올린 뒤 개념 확인, 학습 순서 구성, 설명과 퀴즈, 복습까지 이어지는 도구를 만들었습니다.

### AI 활용 과정

교재를 구역별로 나누고 AI로 개념과 관계를 추출합니다. 사용자가 이해도를 확인하면 이를 학습 순서에 반영하고 선택한 개념의 설명과 퀴즈를 AI로 생성합니다. 복습 시점 계산과 학습 순서 구성 등은 로컬 프로그램이 처리합니다.

AI 호출 방식은 두 가지입니다.

- 사용자 본인의 Claude, OpenAI 또는 Gemini API 키로 앱에서 요청합니다.
- API 키가 없으면 앱의 안내에 따라 프롬프트를 외부 챗봇으로 옮기고 응답을 다시 앱에 가져옵니다.

자료와 학습 기록은 사용자 PC에 저장합니다. AI 처리 시 필요한 입력은 선택한 외부 AI 서비스에 전달됩니다. 중앙 운영 서버 없이 배포하며 API 이용료는 각 사용자의 계정에서 발생하는 구조입니다.

### 확인할 수 있는 결과물

배포본은 1.4.4입니다. 교재 분석 결과를 개념 목록과 학습 플랜으로 확인하고 설명과 퀴즈를 생성해 학습 및 복습에 사용할 수 있습니다. 첫 실행에는 실제 API 분석 결과를 바탕으로 구성한 온보딩 샘플이 포함되어 있습니다.

기존 개발 기록에는 실제 API를 이용한 교재 분석과 레슨 생성, 앱 패키징과 배포, 사용 중 제보에 따른 수정이 남아 있습니다. 이미지 PDF에서 텍스트를 읽기 위한 OCR 처리를 다뤘고 불필요한 항목이 개념으로 추출되는 문제에 대응해 기준을 수정했습니다. 생성한 학습 카드와 사용자 메모의 보존 등도 다뤘습니다.

출처 페이지가 입력 구역의 범위를 벗어나는지 확인하는 검사도 구현했습니다. 페이지 범위의 오류를 가리는 검사이며 설명 내용 전체의 정확성을 보장하는 기능은 아닙니다. 학습 성적이나 학습 시간의 개선 효과를 정량적으로 검증한 결과는 제시하지 않습니다.

### 후속 개발: MCP 연계 (V2, 구현 중)

API 키 없이 사용자가 구독 중인 Claude Code, Codex, Antigravity 같은 AI 코딩 도구를 MCP로 연결하는 V2를 구현하고 있습니다. 검증용 MCP 서버로 세 도구가 레슨을 생성해 앱에 저장하고 다시 조회하는 흐름까지 확인했습니다. 이 기능은 위에서 설명한 1.4.4 배포본에 포함되어 있지 않습니다.

### 배포 및 사용

앱은 별도 저장소에서 배포합니다. 설치 방법과 최신 버전은 [SKALA-FastTrack-releases](https://github.com/tjgurdls9/SKALA-FastTrack-releases)의 Releases에서, 화면별 기능은 [사용 설명서](https://tjgurdls9.github.io/SKALA-FastTrack-releases/guide.html)에서 확인할 수 있습니다. Apple Silicon Mac용이며 Apple 공증을 받지 않아 macOS 보안 설정에 따라 첫 실행이 제한될 수 있습니다.

## 3. Sketch Cleaner

### 개발 배경과 역할

의류회사 실무자의 요청으로 만든 Windows용 작업지 정리 앱입니다. 의류 작업지 사진에는 도해 주변에 손글씨, 표, 붉은 표시가 섞여 있어 도해만 남기려면 하나씩 지워야 했습니다. 요구사항 확인, 사용 흐름과 기능 범위 결정, 단계별 검수를 맡았고 구현에는 AI 코딩 도구를 활용했습니다.

### 처리 과정과 AI의 역할

사진 선택, 원본 확인, 자동 정리, 직접 수정, 확인 후 저장 순서로 사용합니다. 자동 정리를 누르면 앱에 포함된 글씨 감지 모델이 CPU에서 글씨 위치를 찾고, 도해 밖 글씨와 주변 표시를 정리합니다. 도해 안의 표시는 바로 지우지 않고 삭제 후보로 표시해 사용자의 확인을 받습니다. 이후 지우개와 선택 도구로 직접 수정합니다. 원본은 별도로 보존합니다.

사용자는 API 키, 서버, 추가 AI 요금 없이 설치 파일만으로 사용합니다. 모델은 빌드 단계에서 출처와 해시를 확인해 포함하며, 자동 정리 과정에서는 사진을 외부로 전송하지 않습니다.

### 검증과 한계

합성 작업지로 만든 자동 테스트와 Windows 설치 앱 실행 검사를 거쳤고, 실제 작업지 사진에서 정리 결과를 눈으로 확인했습니다. 실무자의 사진은 저장소에 포함하지 않았습니다.

현재는 실무 인수 전 테스트 버전입니다. 실제 사용자 PC에서의 성능, 실무 사진 기준 처리 품질과 업무 시간 비교, 코드 서명은 아직 확인하지 않았습니다. 검은 지시선 일부와 모델이 놓친 손글씨 조각이 남을 수 있어 직접 수정 단계를 두었습니다. 소스와 검증 기록은 [sketch-cleaner](https://github.com/tjgurdls9/sketch-cleaner)에서 확인할 수 있습니다.

## 포함 범위

지원사업 도구의 소스를 포함했습니다. 회사 내부 엑셀과 보고 자료, 개인 API 키와 학습 기록은 포함하지 않았습니다.
